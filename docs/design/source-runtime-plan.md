# Source runtime: implementation plan

Written on 2026-10-04 after the design interview. The decisions are in [source-runtime.md](./source-runtime.md), [ADR 0029](../adr/0029-hosted-programs-link-an-editor-owned-runtime-library.md), [ADR 0030](../adr/0030-cores-resolve-runtime-library-members.md) and [ADR 0031](../adr/0031-projects-pin-the-runtime-abi-not-its-implementation.md); the vocabulary is in [CONTEXT.md](../../CONTEXT.md). This plan covers the first release, the Runtime library for MIPS, RISC-V and RISC-V-64, and outlines the x86 phase. Implementation was authorized on 2026-10-04; milestones 0 to 6 were implemented the same day and are uncommitted, and milestone 7 waits for the owner, since packages are published only on separate instruction. Decisions taken while implementing are under [Implementation notes](#implementation-notes).

## Design notes that settle implementation questions

**Headers.** Compile with `-nostdinc -isystem sysroot/include` and ship our own freestanding headers (`stdarg.h` over `__builtin_va_*`, `stddef.h`, `stdint.h`, `stdbool.h`, `limits.h`, `float.h`) beside the library's. A header outside the supported list is then a clear "No such file" error rather than a mismatched toolchain header. C++ adds `-nostdinc++` and `-fno-threadsafe-statics`, with `<new>`, `<cstdio>`, `<cstdlib>`, `<cstring>`, `<cmath>` and `<cstdint>` wrappers.

**Building the runtime.** The offline build compiles through the Compiler driver itself, so library members come from the same compiler, version and flags as student code. Its outputs are committed: CI assembles and runs them without network access, and a separate, manually triggered job rebuilds and diffs them. Symbol indexes come from the Core, through a build-time API that reports a GNU unit's defined and referenced globals, so the authority on symbols is the same component that resolves them.

**Link model in a Core.** A Build is an ordered list of units, each with its assembler profile. User units come first in each section, then Library members in resolution order. Two staged cases:

1. _All-GNU_ (Generated assembly plus members): GNU units lay out section fragments, export globals and leave fixups, and one link step places every unit and resolves the fixups across units.
2. _Mixed_ (a manual MARS/RARS unit plus GNU members): the legacy first pass over user units fixes their addresses and symbols and yields their undefined globals; members are resolved and laid out after the user segments; their globals enter the global table; then the legacy second pass and the GNU fixups resolve against it.

**Runtime assets.** Generated JSON modules under `src/lib/sourceRuntime/generated/<abi>/`, imported lazily so the bundler gives each its own chunk and the language Worker imports the same ones: `<target>.json` (members, index, member C line maps), `functions.json` (the documented public functions, shared by every Target and small enough for hints and completion), `include.json` (the headers uploaded with every compile) and `sources.json` (the C sources, read when a member's origin is opened). This replaced the `static/runtime/` assets first planned: a module import works the same in the browser, the Worker and the tests.

## Implementation notes

Decisions taken while implementing, on 2026-10-04:

- **Tooling.** The library's sources live in `runtime/`; the tooling that turns them into the editor's assets lives in `scripts/runtime/`: `build.mjs` (Compiler Explorer build, cached by content hash under `runtime/.cache/`, with `--only` and `--dry-run` for development) and `capture-compile-fixtures.mjs` (recaptures the editor's compile fixtures as hosted programs).
- **Library members** are named `@runtime/<abi>/<area>/<function>.s` (`@runtime/v1/stdio/printf.s`, `@runtime/v1/crt0.s`). A Build that links the library rejects a Project File inside `@runtime/` with a diagnostic, since neither path validator can reserve the folder.
- **Loading before the Core.** Emulators load the library in an optional `_prepareBuild` hook, which live checking calls before it waits for an idle Core and Build calls before `_compile`, so check and Build stay synchronous from creating a Core to assembling it. The Worker loads it before its synchronous analysis the same way.
- **Starting.** `RARS.initialize` and `MIPS.initialize` honour their `startAtMain` argument, and an entry symbol takes precedence.
- **Stepping and Undo.** The editor keeps an Undo ledger of plain and grouped stretches (Steps through library code), fed by Step, by Run slices' instruction counts and by Pokes; Undo of a grouped stretch checks the Core's depth (`getUndoDepth`) and undoes it whole or not at all. The History panel folds a stretch into the row of the call that started it, read with `getUndoGroupsRange` so a long stretch is never built. Both Cores gained `getUndoGroupsUpTo/Range` and `getUndoDepth`, which also removed an O(n²) Undo of long histories. `UNDO_HISTORY_SIZE` is 200,000 back steps: measured at about 150 bytes each, about 30 MB once a program has run some 100,000 instructions.
- **MIPS endianness.** MARS memory is little-endian, but the MIPS compiler preset passed `-EB`, a latent bug in the self-contained MIPS path too; the preset, the library build and the fixtures now use `-EL` (Compiler Explorer's MIPS GCC accepts it).
- **MARS's GNU profile** (milestone 6) is a port of the RARS one with MIPS lowering. MARS runs with delayed branching off, so `.set noreorder` code must have a `nop` in every delay slot, as GCC writes it with `-fno-delayed-branch`, and a filled slot is an error; a `jal` therefore returns to its own `nop`. GCC's macros (`move`, `b`, `li`, `la`, `slt` with an immediate) assemble to GNU as's encodings, data directives align themselves and the labels before them as GNU as does on MIPS, and a far conditional branch becomes the inverted branch over a `j`. Every instruction word of the captured GCC fixtures matches GNU as's object code.
- **Every Target compiles hosted programs.** With MIPS linking the library, the self-contained path is gone from [compilerExplorer.ts](../../src/lib/sourceCompilation/compilerExplorer.ts): no renamed `main`, no wrapper, no MIPS section or `slt` rewrites. Output preparation drops debug sections (on MIPS also the `.previous` after `.mdebug.abi32`, which would otherwise swallow the `.nan` and `.module` lines after it, and the `$LFB`-style labels only debug sections use) the same way for user code and Library members.
- **Hand-written MIPS calls** need what O32 asks of any caller: a 16-byte argument area and `$sp` a multiple of 8. MARS starts with `$sp` at `0x7fffeffc`, so a call whose callee stores a double on the stack (`printf("%f")`) faults on the misaligned address. The MIPS Runtime library chapter shows the two instructions it takes rather than the Core starting elsewhere; RARS allows the misaligned store, and `_start` aligns the stack for compiled programs on both.
- **The Explorer** lists the members the current Build linked, read-only, after the Project's Files; go to definition opens any member of the library the live sources would link.
- **A member's C source** opens beside it from a notice above the member; the pair uses the mapped split view through a Source map synthesized from the member's line map, under virtual paths `@runtime/<abi>/src/...`.
- **What real library output needed from the RARS GNU profile**: conditional branch relaxation as GNU as does it (a far branch becomes the inverted branch over a `jal`; layout repeats with the units parsed again until no branch is far, before anything is written); choosing a basic or pseudo form by operand count (GNU writes `fadd.d fs0,fa0,fa0` without the rounding mode); whitespace-proof pseudo template expansion; `.init_array.NNNNN`/`.fini_array.NNNNN` sorted by priority as ld sorts them; and a library-declared `resolveWeak` list, because GCC refers to `__cxa_pure_virtual` weakly from vtables and a weak reference pulls no member.
- **An upstream RARS bug**: jsoftfloat ordered `+inf` below every finite number in `fle.d`/`flt.d`, so `isfinite(inf)` (compiled as `|x| <= DBL_MAX`) was true and `printf("%f", INFINITY)` looped until it ran off the stack. Fixed in `Comparisons.compareNoNAN`.
- **Assembly speed.** Under TeaVM a thrown Java exception costs a native Error with its stack, and token classification threw several per identifier while parsing numbers; together with linear instruction and symbol lookups that made assembly about 600 µs per line. Guarding the number parse and indexing instructions and symbols by name brought both dialects to about 60 µs per line, which matters now that every Build and live check of a linked program also assembles its Library members. A `printf` program on RISC-V links 22 members (about 4,000 lines) and assembles in about 430 ms; branch relaxation parses again only the units with a new far branch. What remains is mostly RARS's string-built statement encoding. MARS's GNU path assembles at about 25 to 45 µs per line.
- **Symbol names that are also operand names.** A CSR name (`time`, `cycle`) or rounding mode is a symbol except where the instruction takes one, so a program calling `time()` pulls its member; numbers and numeric labels are never references; `.type v, @gnu_unique_object`, which C++17 inline variables produce, is accepted. GCC also refers to `__cxa_deleted_virtual` weakly, so the library declares it in `resolveWeak` beside `__cxa_pure_virtual`.
- **The ABI baseline** is `runtime/abi/v1.json`: 174 exported names and the 56 layout entries of `runtime/abi/layout.c` for each of the three Targets.
- **Clang**, which the compile dock offers and makes the default since 2026-10-04, is checked on the corpus too (`test-cores.mjs --compiler clang`). Its output needed RARS to accept `unimp`, which Clang writes after code that cannot be reached and GNU as encodes as a trapping write to the read-only `cycle` CSR, and a soft-float fix: Clang contracts `a*b+c` into `fmadd`, and an addend of zero or infinity crashed the Core asking it for an exact value. The library gained `bcmp`, which Clang calls for a `memcmp` only compared with zero, and `malloc_test` keeps its huge allocations observable through a `volatile` pointer, since LLVM drops an allocation that is only compared with NULL, and reads `errno` through volatile accesses, since LLVM assumes the allocation functions never set it (a limitation FUNCTIONS.md records). The corpus passes with both compilers, 426 of 426 each.
- **Licence.** The code written for the library is under the repository's AGPL-3.0 with a linking exception, [runtime/LICENSE-EXCEPTION.md](../../runtime/LICENSE-EXCEPTION.md), worded after the GNU Classpath exception: a program that links Library members may be distributed under any terms, while the library itself stays AGPL. The musl-derived files keep musl's MIT licence.
- **An unknown Runtime ABI** in a Compilation record (a Project saved by a newer editor) shows a notice above its Generated assembly, and the dock's action becomes Recompile, as it does for stale assembly. The Build error names the remedy by where the ABI came from: Recompile for a record's, the Setting for the Setting's.
- **Where a Build stops.** A Build that starts in library code runs it with the Core's Undo recording paused (`setUndoEnabled`, through the adapters' `_setUndoRecording`) until the next instruction is user code, so the Debug session opens on `main`, or on a C++ global constructor, rather than on `_start`, and Undo stops there. The start code reads no input and writes no output before user code, so nothing it does is visible. Testcases still start at `_start`, so their starting registers and instruction limit apply where they always have; the _Step into Runtime library_ toggle keeps the Build at `_start`.
- **The Core corpus runner** (`scripts/runtime/test-cores.mjs`) compiles each corpus program as the editor does, links the generated library through the Core, and compares output, exit status and Files with the glibc oracle the native harness stores; a stress program can raise its instruction limit with a `core-instruction-limit: N` comment.

## Milestones

Dependency-ordered. RISC-V leads because its GNU profile is underway; MIPS follows once MARS has one.

### 0. Function list and corpus

- Write `runtime/FUNCTIONS.md`, the supported list for ABI `v1`, from the five accepted program cases: stdio on the Terminal and Files (`printf`/`scanf` families, `fgets`, `fopen`/`fclose`/`fread`/`fwrite`/`fputs`/`fgetc`/`ungetc`/`feof`/`ferror`), `malloc`/`calloc`/`realloc`/`free`, `qsort`/`bsearch`/`strtol`/`strtod`/`atoi`/`abs`/`rand`/`srand`/`exit`/`atexit`/`abort`, `<string.h>`, `<ctype.h>`, `<math.h>`, `time`, and C++ support (`operator new`/`delete`, `__cxa_atexit`, `__dso_handle`, `__cxa_pure_virtual`). Mark musl-derived entries.
- Derive the syscalls the Cores must provide: at least `lseek` (missing in MARS, commented out in RARS) and time.
- Write the corpus as C and C++ programs under `runtime/tests/`, with expected output generated by building each program natively against host glibc and capturing its output. Include scripted-input cases with End of input and FileSystem cases.

Exit: every listed function has at least one corpus case and an expected output.

### 1. Platform contract and Core syscalls

- Write `runtime/PLATFORM.md`: for each Target, syscall numbers, registers, return values, error convention, descriptor 0–2 semantics and End of input.
- MARS and RARS: change `stdIn` to an asynchronous handler returning a byte count (0 for End of input), following the existing asynchronous input syscalls; add the missing syscalls from milestone 0; make the start label configurable (`entrySymbol` option, default unchanged).
- Editor: a descriptor-0 line buffer in the [Terminal](../../src/lib/languages/peripherals/Terminal.svelte.ts) that requests one line per refill through the existing prompt/Keyboard path and echo rules; End of input from Ctrl+D and a visible button in the input prompt; scripted exhaustion returns End of input for descriptor-0 reads only, while the educational read syscalls keep the "no input left" error. Wire `stdIn` in both adapters.

Exit: Core package tests and editor tests cover short reads, leftover bytes, End of input interactive and scripted, and unchanged behaviour of existing Testcases.

### 2. RARS linking

Depends on milestones 1–3 of the RISC-V compatibility plan (expressions, layout, relocations).

- Multi-unit builds in the all-GNU case: the factory takes `units` (path plus profile) instead of one Entry; per-unit locals, including `static` names and `.L` labels; cross-unit fixups; numeric labels scoped per unit.
- Archive resolution with ADR 0030's semantics: `libraries: [{ members, index }]`, iteration until no new undefined global, user definitions first, multiple-definition errors naming both Files, and unresolved-symbol errors on the referencing line. The index-reporting API for the offline build.
- The mixed case: legacy RARS user units followed by GNU members, in the order described above, with existing RARS programs byte-identical when no member is pulled.
- Diagnostics, Step, breakpoints and stack frames carry member File identity.

Stop and discuss if the mixed case needs the legacy assembler to stop writing memory during its first pass.

### 3. Runtime library for RISC-V

- `runtime/` layout: `include/` (library and freestanding headers), `src/<area>/<function>.c`, `arch/riscv/syscall.h` (inline-assembly wrappers), `arch/riscv/crt0.s` (`_start`: stack alignment, `.init_array`, `main(0, NULL)`, `exit`), `third_party/musl/` with its licence, `scripts/build.mjs`.
- Implement to the constraints: write-through streams with `fflush`/`setvbuf` as successful no-ops; static stream initialization and lazy heap set-up, so no function needs `crt0`; `stdin` line buffering in the library over the Core's tty semantics.
- The build produces members, index, metadata and Source maps for RV32 and RV64, plus an ABI baseline (exported symbols, plus struct layouts from a generated `offsetof`/`sizeof` table), and fails if a later build of `v1` changes either.
- Corpus runner: assemble and run every corpus case on the Core in Node, from C through `crt0` and from bare assembly without it, and compare against the glibc expectations.

Exit: the corpus passes on RV32 and RV64 at O0 and O2.

### 4. Editor integration for RISC-V

- **Compiler driver:** extract a `CompilerDriver` interface (`compile(units, sysroot, preset) → assembly, map, diagnostics`) from [compilerExplorer.ts](../../src/lib/sourceCompilation/compilerExplorer.ts); upload the sysroot with every request and check the request against the 1 MiB limit with headers included; delete the wrapper and `-Dmain`; leave only the debug-material stripping the GNU profile does not yet ignore.
- **Settings and records:** a _Link Runtime library_ Setting (`off | v1`, default `off`) in [projectSettings.ts](../../src/lib/projectSettings.ts) with strict validation; a required `runtimeAbi` in [records.ts](../../src/lib/sourceCompilation/records.ts) written by [compileProjectSource.ts](../../src/lib/sourceCompilation/compileProjectSource.ts) and enforced over the Setting for that Entry; an unknown ABI blocks Build with a Recompile action.
- **Build sources:** `runtimeAbi` and resolved `libraries` in [BuildSources](../../src/lib/projectFiles.ts), carried through [WorkbenchSession](../../src/lib/workbench/WorkbenchSession.svelte.ts), snapshots, Testcases, [GenericEmulator](../../src/lib/languages/GenericEmulator.svelte.ts) equality and [RISC-VEmulator](../../src/lib/languages/RISC-V/RISC-VEmulator.svelte.ts), which passes units, libraries and `entrySymbol: '_start'` for Generated assembly.
- **Library Files:** members appear as read-only Files under a reserved namespace in the Explorer and debugger, outside the program-visible FileSystem, never persisted, shared or archived.
- **Language service:** the Setting and libraries in the worker [protocol](../../src/lib/languages/service/protocol.ts), [server](../../src/lib/languages/service/workers/projectWorkerServer.ts) and [adapter](../../src/lib/languages/service/adapters/marsAdapter.ts), with setting-only changes starting a new revision; completion, hover and signature help from the metadata; go to definition into members and their C source; library symbols read-only for rename. With the Setting off, an undefined indexed symbol carries the Hint.
- **Documentation:** generated Runtime library entries per Target, which search indexes like any other entry.

Exit: compiled C and C++ programs from the corpus Build, Run and debug in the editor; a manual RARS program calls `printf` with the Setting on; existing Projects are unchanged with it off.

### 5. Stepping and Undo around library code

No Core-native grouping: Undo returns to the previous stop by popping the instructions the last Step ran, through the editor's existing `undo(amount)`. FileSystem and Screen journals already work per instruction and need no change.

- MARS and RARS: make the backstep stack allocate its slots on first use instead of all at once when assembling, and raise the editor's history limit behind the unchanged on/off _Undo_ Setting until a long `printf("%f")` and a moderate `qsort` fit. Measure entries per call, memory per entry and Build time, and pick the limit from those numbers; small programs pay nothing up front.
- [GenericEmulator](../../src/lib/languages/GenericEmulator.svelte.ts): when Step lands in library code, run under the existing scheduler until the program counter is back in user code, stopping for breakpoints, input Interrupts, exit and errors. Each Step records how many instructions it ran (1 normally), and Undo pops that many. If the history no longer holds all of them, Undo is unavailable for that Step, as it is past the oldest kept entry today; it never lands partway through library code. Run keeps today's per-instruction Undo.
- History panel: in the default mode a library stretch shows as one row (for example `printf: 1,234 instructions`) whose _Undo to here_ returns to before the call.
- The Workbench toggle _Step into Runtime library_ restores ordinary stepping and per-instruction Undo and allows breakpoints in members.

### 6. MIPS

- A GNU profile for MARS, ported from `GnuAssembler` (RARS forked from MARS, so the assembler structure matches), covering GCC's MIPS32 little-endian output with the current preset; then retire the MIPS rewrites in `prepareAssembly`.
- Milestones 2 and 5 for MARS, the MIPS syscall layer and `crt0.s`, the corpus on MARS, and editor wiring in [MIPSEmulator](../../src/lib/languages/MIPS/MIPSEmulator.svelte.ts).

### 7. Release

- Core releases follow the emulator release recipe, then the editor dependency bump.
- Enable the Setting and the `runtimeAbi` requirement for new compilations only after the RISC-V corpus passes in the editor; MIPS joins when milestone 6 passes. Old Compilation records without `runtimeAbi` keep today's behaviour until recompiled.
- Update the Source compilation documentation and courses that describe the self-contained boundary.

## x86 phase (outline)

A separate plan, after the first release: an x86-64 syscall layer over blink's Linux syscalls; members built through the GCC `-masm=intel` to NASM translator that x86 Source compilation will use, then linked as an archive by the Core's existing `ld` step; `crt0` running `.init_array`; the same corpus run on the Core and natively. The translator findings are in the x86 compilation research recorded on 2026-10-04.

## Risks

- **Mixed-profile linking** is the largest new Core work and depends on the GNU profile's layout model; it is staged after the all-GNU case so compiled programs are not blocked by it.
- **History size:** a larger limit costs memory per entry; the lazy stack keeps small programs cheap, and the limit is chosen from measurements.
- **Header size:** the sysroot uploads on every compile, so the headers stay declarations only, and the driver test asserts the request size.
- **musl-derived code** must pass the GNU profiles; anything that does not is replaced or simplified, never silently dropped.
