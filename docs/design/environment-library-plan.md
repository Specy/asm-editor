# Environment library: implementation plan

Written on 2026-10-05 after the design interview. The decisions are in [environment-library.md](./environment-library.md) and ADRs [0034](../adr/0034-environment-library-is-header-only.md) (header-only `<sim.h>`), [0035](../adr/0035-environments-match-their-reference.md) (every environment matches its Reference environment), [0036](../adr/0036-programs-read-input-typed-in-the-terminal.md) (input typed in the Terminal) and [0037](../adr/0037-testcases-run-on-a-seeded-random-source.md) (seeded Random source); the departures they correct are listed in the [audit](../research/environment-services-audit.md); the vocabulary is in [CONTEXT.md](../../CONTEXT.md). The plan covers `<sim.h>` for MIPS, RISC-V and x86, the Terminal's Line discipline, the run contract shared by every Core, and one release of each Core that changes (MARS, RARS, s68k, Blink). Implementation was authorized on 2026-10-05 and completed on 2026-10-07; the continuation used Sol subagents as the owner requested. The owner subsequently authorized all four releases and confirmed their npm publication; the editor now consumes the published packages. Decisions and verification evidence are under [Implementation notes](#implementation-notes). Owner manual checks remain. The [release recipe](#releases) below is historical.

## Decisions taken while planning

Recommended by the planning pass and confirmed by the owner on 2026-10-05.

1. **x86 inline assembly (M2).** The translator accepts a bounded inline-assembly subset: an `#APP` block whose lines are instructions and directives it already translates from GCC's Intel output. `<sim.h>` uses only `syscall` with register-bound operands. Hand-written NASM wrappers were the alternative, but they would sit outside the student's Generated assembly, against ADR 0034. ADR 0034 carries the amendment.
2. **Heap after static data (M5).** In GNU-profile Builds, MARS and RARS start the heap (and `sbrk`) at the first page after static data when static data passes the default heap base. A real `ld` and kernel do the same, and it lifts the `SIM_SCREEN` cap. Until then, `SIM_SCREEN` rejects a grid above the cap at compile time with a message that names the limit.
3. **`-iquote .` instead of `-I .` (M0).** Quoted includes find Project Files; angle-bracket includes find only the system headers, as GCC behaves without `-I`. A Project's `sim.h` or `stdio.h` then never shadows the library's.
4. **M68K text is Windows-1252 in the assembler too (M6).** The s68k assembler maps the 27 Windows-1252 characters of `0x80`–`0x9F` (`€`, curly quotes, ...) and its ADR 0004 is amended. Keeping Latin-1 would leave EASy68K sources that use them failing to assemble.
5. **Float formatting reference (M5).** MARS and RARS as they run on a current JDK (21): the shortest decimal that round-trips, in Java's layout (`1.0`, `1.0E-5`, `1.0E7`), computed by our own code in the Cores rather than TeaVM's. Parsing checks Java's grammar, then parses correctly rounded. Golden vectors are produced by a JDK 21 program.
6. **Undo restores generator state (M5, M7).** MARS and RARS journal a stream's state when a random service advances it. On x86, `getrandom`'s stream position is recorded with the instruction. Undo then Step returns the same number again, as ADR 0005 already holds for the Screen.
7. **x86 Undo before file and standard input effects (M7).** An instruction that changes a File or consumes standard input is recorded as irreversible, so Undo stops before it rather than leaving files and input out of step with memory. Journaling them (ADR 0015) is a later milestone.
8. **MARS print string has no length limit**, as MARS 4.5 has none. Corrected on 2026-10-06: the decision first kept a 65,536-character error on the false premise that MARS has one; it was this fork's own, and it is dropped, per ADR 0035.
9. **The EASy68K cycle counter (30, 31) needs a 68000 cycle-timing model.** It is a later milestone, and the tasks stay rejected with a reason until then. An instruction count would be a deviation that does not help the learner.
10. **A read in a host whose console is hidden reveals it.** The Interactive editor opens its console; the Workbench selects and unfolds the Terminal; the input caret takes focus.
11. **`<sim.h>` is a committed, generated asset per Target**, with a test that regenerates it from the data and compares. Only the Target's text is uploaded. It stays out of `include.json`, which is versioned with the Runtime ABI and rebuilt over the network.
12. **The Terminal transcript is not rewound by Undo.** That gap predates this work and is left out of it.

## Milestones

### M0: Groundwork in the editor

- Move the MIPS and RISC-V syscall data into Core-free modules that the Documentation, the generator and tests import. Add to each entry:
    - its C binding: function name, parameter names and C types, the register each binds to, and how results come back;
    - `noreturn` for the exit services;
    - an `implemented` flag, false for 40 until M5.
- Results come back as a return value, or through out-parameters for multi-result services. Time's two halves become a `long long`; dialogs 51–53 return the value and write the status through a pointer.
- Fix the RISC-V result registers (`a0`/`fa0`) and add the lseek (62) entries.
- Replace `-I .` with `-iquote .` (decision 3) in the compile request and in `scripts/runtime/build.mjs`'s corpus compiles; test that a Project-root `stdio.h` no longer shadows `<stdio.h>`.
- Teach the x86 documentation generator Blink's configuration. A small evaluator over the eight guard macros `syscall.c`'s table uses, read from the checkout's `config.h` (from M7, the committed one), keeps only compiled calls. Add `time` (201); flag `sync` and `mknod`, which compile but return ENOSYS. Regenerate `x86Syscalls.ts`, fix the "a call listed here is a call that works" claim, `X86_COMMON_SYSCALLS` (`brk`) and the pinned counts in `x86.test.ts` and `X86-documentation.test.ts`.

Done when the Documentation renders unchanged apart from the fixes, and the x86 syscall page lists only calls that run.

### M1: `<sim.h>` for MIPS and RISC-V

- **Generator** (`scripts/sim-header/`): reads the M0 data and the device constants of `documentation/mars/screen.ts`. It writes `src/lib/sourceRuntime/generated/sim/<target>.h` for `mips`, `riscv32` and `riscv64`, and a vitest drift test regenerates and compares. Each `sim_` function is `static inline`, with:
    - register-bound locals (`register int v0 __asm__("$2")`, `register long a7 __asm__("a7")`);
    - `__asm__ volatile` with `syscall` or `ecall`, and a `memory` clobber;
    - `__attribute__((noreturn))` on the exit services;
    - its Documentation description as a one-line doc comment;
    - `extern "C"` under C++.
- **Devices.** The keyboard and display registers get `sim_keyboard_ready`, `sim_keyboard_read`, `sim_display_ready` and `sim_display_write`, as volatile accesses at `0xFFFF0000`–`0xFFFF000C`.
- **`SIM_SCREEN(name, width, height, unit)`** defines a word-aligned `unsigned name[]` grid and emits `# @screen width=... height=... unit=... base=name` through a file-scope `__asm__`, with a `_Static_assert` on the grid size against the static-data cap (decision 2). `sim_rgb(r, g, b)` builds a color.
- **Upload.** `compileSource` adds the Target's `sim.h` to the sysroot for MIPS, RISC-V and RISC-V-64.
- **Output filter.** It keeps `@screen` comment lines (the `#APP`/`#NO_APP` markers still go), in `compilerExplorer.ts` and `build.mjs` alike.
- **Source map.** Lines whose source is `sysroot/include/sim.h` map to the read-only `@runtime/include/sim.h`:
    - `projectPath` learns the path, and line counts come from the header text;
    - the path is left out of a Compilation record's inputs and fingerprints;
    - `parseRuntimeSourcePath`, `mappingPair.ts` and `WorkbenchSession.runtimeMemberFile` accept it;
    - the C pane highlights inside it;
    - Step is unchanged, since the instruction belongs to the student's unit.
- **Documentation.** Each MIPS and RISC-V syscall entry gains a _From C_ field with its prototype, after the Runtime library chapter's _Declaration_ field.
- **Tests.** Captured compile fixtures (GCC and Clang, `-O0` and `-O2`, MIPS, RV32, RV64) calling every implemented service run on the Cores, with scripted input where a service reads. A `SIM_SCREEN` fixture draws a pixel that `visiblePixels` shows. A header diagnostic lands on `@runtime/include/sim.h`. In the browser: compile, Build, Step into an inlined `sim_print_int` and back.

### M2: `<sim.h>` for x86

- **Core (`@specy/x86` 4.1.0):** the translator accepts the bounded inline-assembly subset (decision 1), with tests in the translator's corpus and a user `asm("nop")` example.
- **Generator.** Adds `x86_64.h` from the filtered `x86Syscalls.ts`:
    - pointer-like strace labels become `void *`, everything else `long`;
    - each function returns the raw `long` result (a negative errno);
    - `exit` and `exit_group` are `noreturn`;
    - `rcx` and `r11` are clobbered.
- **Editor.** `X86_HEADER_NAMES` gains `sim.h`, and the freestanding-header hint mentions it.
- **Tests.** x86 fixtures through the interim Start unit print, read a line and exit with a code, and calling a service the Core lacks (`sim_fork`) is a compile error naming the function, not a runtime ENOSYS.

### M3: The Terminal's Line discipline and component

- **Terminal (`peripherals/Terminal.svelte.ts`):**
    - **Input queue and reads.** It gets its own typed-input queue, shared with the Screen Keyboard through the existing `TerminalKeyboard` shape, and a Line discipline:
        - a line read edits until Enter (Backspace, paste, IME commit) and echoes;
        - a character read returns on one keystroke, with Enter given as the Target's code (10, `$0D`);
        - Ctrl+D and the End of input button answer standard input with End of input.
    - **Reactive read state.** A reactive pending-read state (kind, Target, whether End of input applies) is exposed for the view.
    - **Output.** A byte writer takes a per-Target streaming decoder (UTF-8 for MIPS, RISC-V and x86, Windows-1252 for M68K, Latin-1 for the Z80), configured where `GenericEmulator` constructs the Terminal. An SGR-colour and clear-screen parser applies to x86 output only.
    - **Dialogs.** A dialog API with Cancel answers and no echo.
    - **Cleanup.** The prompt branches and `promptStore`'s `askLine`/End of input go. `eraseEcho` is fixed for astral characters. `hasPendingInput` reads the queue. A `readByte` serves the Z80 adapter, which stops peeking at `inputSource`/`interactiveSource`.
- **Component.** `TerminalConsole.svelte` replaces `Console.svelte` in `TerminalView` and `StdOutRenderer`:
    - it renders the transcript from the Terminal, with a caret where a read waits;
    - a visually hidden `textarea` takes focus, IME and phone keyboards (`inputmode`), and `app.html`'s viewport gains `interactive-widget=resizes-content`;
    - keys follow `ScreenRenderer`'s propagation rules, so Workbench shortcuts do not fire while typing;
    - a read in a hidden host reveals it (decision 10).
- **Modal.** The modal remains for the app's own dialogs and for MARS/RARS dialogs. Confirm gains Cancel. Message dialogs become an awaited Prompt alert instead of `window.alert`.
- **Dependency.** Remove `@battlefieldduck/xterm-svelte` (`package.json`, the lockfile, `vite.config.ts`).
- **Adapters, with the current Cores:**
    - M68K tasks 2, 4, 5 and 18 read through the Line discipline;
    - MIPS and RISC-V `readChar` is a character read (one character still satisfies the Core's length check);
    - x86 standard input uses `readStandardInput(maxBytes)`. The Terminal now keeps the leftover bytes and an empty answer gives End of input, so x86 `read(0)` behaves like a tty before Blink changes, apart from `readv` and `dup`'d descriptors.
- **Content.** The seven Lectures that mention "the input box under the console", `runtime-library.md` (MIPS, RISC-V) and `docs/manual-verification.md`.
- **Tests.** `Terminal.test.ts` (Line discipline, Enter codes, End of input, decoders, SGR); a `TerminalConsole.svelte.dom.test.ts`; the adapters' input tests; `content.test.ts`. In the browser: typing a line and a single key on each language, Ctrl+D on x86 and MIPS, a phone viewport, a Playground with a console and one without.

### M4: The run contract in the editor

- **Random source.** A new `peripherals/RandomSource` (host randomness, or a fixed seed with per-generator derivation) is injected beside the clock. `useScriptedRun` and `useInteractiveRun` swap it, the reset restores it, and adapters read it at the point of use. Tests cover the Testcase swap and the reset.
- **Termination.**
    - `BaseEmulator` reports `{exitCode?, cause}`, a normal end, an exit with a code, a signal or a runtime error, and `GenericEmulator` keeps it beside `terminated`, reset by `clear` and Undo.
    - Step goes through the shared `reportRuntimeFailure`.
    - The Log's `exitEntry` shows "exited with code N" and signals as "Segmentation fault (signal 11)", and Step-to-exit logs too.
    - The Interactive editor's info line and the coding agent's status tool use the same text, and `FakeEmulator` gains the member.
    - The x86 adapter maps the Core's existing `exit`/`signal` stop reasons now, masking the status to 0–255 until M7.
    - M68K's unreachable "Program terminated with errors" branch is deleted.
- **FileSystem session.** The session gains read-write handles, typed guest error codes, `stat`, `truncate`, caller-chosen descriptor ranges and limits, and `closeAll`, for M68K tasks 50–59 and the x86 backend.
- **MARS/RARS handlers.** The duplicated handlers move into `languages/mars/marsHandlers.ts`, with behaviour unchanged; only the `programCounter` accessor and the step result differ per Core.

### M5: MARS and RARS 4.0.0

Both Cores, mirrored unless noted:

- **Printing.** Every print service formats in Java through `printString` (the `printInt`/`printFloat`/`printDouble`/`printChar`, `ask*`, `log` and `logLine` handlers go), with float and double formatting as in decision 5.
- **Reading numbers.** Read int, float and double take the raw line from the handler; `SystemIO` trims and parses with the reference's rules and raises "invalid integer input (syscall 5)" with the statement address.
- **Dialogs.** `inputDialog` may answer null, which becomes -2 (and 2 for confirm), and message dialogs are awaited.
- **Handler shapes.** `writeFile` returns the count or -1, byte arrays cross as `number[]`, and unused arguments go.
- **Random numbers.**
    - A `JavaRandom` class is used by one `RandomStreams.get(index)`, seeded through a new `randomSeed(index)` handler.
    - Service 40 is registered in both Cores (loader and properties).
    - Streams reset in `initialize`, and the BackStepper journals a stream's state (decision 6).
- **Exit.**
    - `exitCode` is exposed and reset in `initialize`.
    - `terminated` is derived from the exit or from no statement at the program counter, so it is right after Undo, and `getNextStatement` stops after an exit.
    - Every run call returns a `StopReason`, MARS's constants mapped to RARS's order.
    - Failures reject with a typed error `{kind, address, line, message}`.
- **Static data.** The heap starts after static data in GNU-profile Builds (decision 2).
- **MIPS only:**
    - UTF-8 throughout: the assembler stores literals by code point, and print string, read string, dialogs and open use a `NullString` helper;
    - print char and read char follow RARS;
    - exit sets code 0;
    - print string has no length limit, as MARS 4.5 (decision 8, corrected).
- **RISC-V only:**
    - GetCWD returns a fixed path;
    - 53 reads its message from `a0`;
    - the `time` CSR reads the time handler, so it is virtual in a Testcase.
- **Tests (Node, on `dist`):**
    - golden vectors from a JDK 21 program (`toString`, parse, `java.util.Random` sequences per service, seeds 0, 42 and negative);
    - exit codes and `StopReason`s after exit, cliff and Undo;
    - a null dialog answer;
    - UTF-8 round trips;
    - generator Undo.
    - `HANDLER_NAMES` and the READMEs are updated.
- **Editor:**
    - `marsHandlers.ts` adopts the new shapes;
    - `ended`, `handlerBytes`, `readNumber` and `readCharacter` are deleted;
    - Cancel reaches the program, and the Random source feeds `randomSeed`;
    - the MIPS and RISC-V exit tests are rewritten;
    - 40 is marked implemented, and `<sim.h>` is regenerated with `sim_random_seed`;
    - the Documentation's exit2, time, 40–44 and lseek entries are updated.

### M6: s68k 3.0.0

- **Core:**
    - **Text.** Windows-1252 decoding and encoding in tasks 0, 1, 2, 5, 6, 13, 14, 17, 18 and 95, and in the assembler (decision 4, s68k ADR 0004 amended).
    - **Formatting.** Output formatted in the Core for 3, 15 (uppercase, base error kept as a documented deviation), 17 and 20 (signed width).
    - **Reading.** Raw-line answers for 2, 4 and 18, with `atoi` semantics, the 79-character cap and D1.L. A key answer for 5, with Enter as `$0D`.
    - **Clipping.** Tasks 0 and 1 clip at 255 and stop at a NUL.
    - **Settings.** Echo (12) and prompt/LF settings (16) as Core state journaled for Undo, which the adapter passes to the Line discipline.
    - **Files.** Tasks 50–59 as interrupts with byte-safe answers (a dedicated wasm method, since serde passes `Vec<u8>` as number arrays). Results follow EASy68K: D0.W 0/1/2/3, eight handles from 0, short-read and end-of-file rules for 53, absolute seek for 55. 58's dialog is answered by the modal Prompt.
    - **Errors.** Typed errors (`UnsupportedTrapTask {task}`, invalid arguments), every task error ending the program, answers validated against the pending interrupt instead of panicking.
    - **Sound.** Interrupt variants for 70–77 only, rejected by the adapter until the Audio Peripheral.
    - **Updated:** the CLI, the corpus policy table and snapshots, the README.
- **Editor:**
    - **Removed:** `readNumber`, `padStart`, `toString(base)`, the "Unknown interrupt" regex and the dead branch.
    - **Files.** Tasks 50–59 run on the FileSystem session, with frames keyed by the Core's step id and the Undo preflight as MIPS has.
    - **Tables and docs.** The rejected-task table: 12 and 16 become implemented; 30 and 31 keep a reason (decision 9); sound, serial and network gain reasons. Update `traps.md` and the Lectures on trap #15.
    - **Tests.** `M68KEmulator.test.ts`, `ScreenUndo.test.ts`, the M68K Examples and Exercises.

### M7: Blink 5.0.0

- **Core, in order** (sizes from the planning pass: S under a day, M one to three days, L more):
    1. A committed, deterministic build configuration, with `DISABLE_NONPOSIX` off and the needed `HAVE_*` forced (S).
    2. Host hooks for clock, randomness and waits, routed through one `HostNow` and one `GetRandom` (also the loader's `AT_RANDOM` and `/dev/urandom`), plus a monotone `instructions_executed` (M).
    3. The pure-state syscalls (`brk`, `dup3`, `prlimit`, `close_range`, `preadv`/`pwritev`, `renameat2`, `sysinfo`, `sendfile`, `prctl`, the `res*id` family, the clock ids) and a Core-exported syscall list that the documentation generator reads (M).
    4. Standard streams as Blink `FdCb`s: a standard-input byte buffer with End of input for `read`, `readv`, `pread` and `dup`'d descriptors; `read(0, buf, 0)` returning 0; tty `ioctl`s so `isatty` is true; output in chunks; `provideInput(bytes | EOF)` (M).
    5. Asynchronous waits through a new halt-and-resume trap, with the cleanup `ExitTrap` does, for `nanosleep`, `clock_nanosleep`, `select`, `poll`, `ppoll`, `pause` and `sigsuspend`, ending the busy-wait and the `poll` abort (L).
    6. Signals to itself: `kill`, `tkill` and `tgkill` on its own process, `wait4` as ECHILD, `alarm`/`setitimer` on the host clock delivered at wait wake and slice start, and SIGTRAP's default action (M).
    7. Exit status masked to 0–255; signal number, code and name in the stop reason (S).
    8. The launch line and banners removed (S).
    9. Per-run isolation: close leaked descriptors, protect 0–2, reset MEMFS, hide `/linker`, `/program.o` and `/program` (keeping the bytes in JS) (M).
    10. An Emscripten file-system backend over the editor's FileSystem session, mounted as the working directory, with frames keyed by the history serial (L).
    11. Instructions that change a File or consume standard input recorded as irreversible (decision 7) (S).
- **Editor:**
    - the adapter wires the clock, wait, random and FileSystem hooks and drops its output filter and line-ending patch;
    - Testcases run on the virtual clock and the seeded source;
    - the documentation generator reads the exported list;

## Order and dependencies

```
M0 ──► M1 ──► M2
 │
 └──► M3 ──► M4 ──┬──► M5 (MARS, RARS) ──┐
                  ├──► M6 (s68k)        ├──► M8
```

- **No release:** M0 and M1 need none, so `<sim.h>` reaches MIPS and RISC-V first.

## Risks

- **Changed output in saved Projects.** A saved Project's Testcases written against today's output fail after M5 and M6: `1` becomes `1.0`, `ff` becomes `FF`, Enter becomes `$0D`, an empty number line is now an error. ADR 0035 accepts this; the release notes say it.
- **Unverified edge cases.** Borland's `atoi` on overflow and EASy68K's behaviour for D1.W of `$8000` and above in tasks 0 and 1 are unverified; implementation picks and documents one. TeaVM's treatment of `undefined` as a null dialog answer is unverified; the handler returns `null` explicitly.
- **Emscripten file-system backend.** It is the largest single item; if it slips, M7 can ship items 1–9 and 11 with Project Files still invisible, as today.
- **Header size.** `x86_64.h` with about 110 functions stays far under the 1 MiB request; the drift test reports its size.

## Implementation notes

Decisions taken while implementing, recorded as each piece lands.

- **FileSystem session (M4, 2026-10-05).**
    - **API.** `FileSystemGuestError` carries a `FileErrorCode` named after errno: ENOENT, EEXIST, EBADF, EISDIR, ENOTDIR, EMFILE, ENOSPC, EFBIG, EINVAL, EACCES.
        - `beginSession` takes `{firstDescriptor, maxOpen}`; M68K passes `{0, 8}`.
        - `open` takes an options object for `read-write`, create, exclusive, truncate and append, beside the three old mode strings.
        - New: `closeAll`, `pread`, `pwrite`, `truncate`, `ftruncate`, `stat`, `fstat` (for a File removed while open) and `list`.
    - **Undo.** Every mutation journals into the instruction's frame before it happens, and checks run first, so a failed operation leaves nothing behind.
    - **Capacity.** The Project limits are guest errors: ENOSPC for 16 MiB or 4,096 Files, EFBIG for one File over 16 MiB.
    - **Deviations from POSIX.** Creating a File creates its Directories (there is no mkdir). `rename` neither replaces a File nor moves a Directory. A Directory cannot be opened.
    - **Linux flag semantics.** O_TRUNC truncates whatever the access. O_EXCL is ignored without O_CREAT. `pwrite` ignores O_APPEND.
- **Syscall data and C bindings (M0, 2026-10-05).**
    - **Where the data lives.** The MIPS and RISC-V syscall entries live in Core-free modules (`src/lib/documentation/mars/mipsSyscalls.ts`, `riscvSyscalls.ts`, types and `simPrototype()` in `syscallBinding.ts`). The language Documentation modules re-export them, and `documented()` hides services marked not implemented.
    - **Binding shape.**
        - Registers are spelled as the Documentation spells them (`$a0`, `fa0`), so the generator writes MIPS general registers by number.
        - Dialog statuses are `out` pointer parameters.
        - Time returns `{low, high}`, with the low half read unsigned because RV64 sign-extends.
        - `clobbers` lists other registers a service changes (RISC-V 53 zeroes `f0`).
    - **Names, shared by both Targets.** `sim_print_char(int)`, `void *sim_sbrk(int)`, `sim_read_string(char *, int)`, `sim_read`/`sim_write(int, (const) void *, int)`, `int sim_lseek(int, int, int)`, `long long sim_time(void)`, `sim_random_*(int generator, ...)`, `sim_confirm_dialog`, `sim_input_dialog_{int,float,double}(const char *, int *status)`, `int sim_input_dialog_string(message, buffer, size)` (returns the status), `sim_message_dialog[_int|_float|_double|_string]`. `sim_exit` and `sim_exit2` are `noreturn`; `int sim_get_cwd(char *, int)` is RISC-V only.
    - **Documentation fixes.** RISC-V register fixes: results in `a0`/`fa0` (52 keeps `f0`, as RARS writes it); arguments of 2, 3 and 58 in `fa0`, 60 in `fa1`. Both Targets gain 62, "lseek (move file position)", an addition to MARS 4.5 noted as such.
    - **Not implemented until M5:** RISC-V 17 (GetCWD crashes on every call) and 40. RISC-V 53 reads its message from `x4` until M5 fixes the Core.
    - **Include flags.** Every compile passes `-iquote .`; `compilationInputs` follows quoted includes only. Known and unchanged: Compiler Explorer compiles the main source at the request root, so a quoted include from `src/main.c` finds a root header before one beside the source, which `compilationInputs` does not model.
- **x86 syscall list (M0, 2026-10-05).** `scripts/x86-docs/preprocessor.mjs` evaluates the `#if` guards around `syscall.c`'s table from `config.h` and the macros `blink/thread.h` derives.
    - **Unknown macros.** A macro the configuration does not name stops the generator with its file and line, rather than being guessed.
    - **Where the configuration comes from.** It is chosen only in `readBlinkConfiguration` (`blinkConfigPath`), so M7's committed configuration, or a Core-exported list replacing `readBlinkSyscalls`, is a one-place change.
    - **The list.** It has 111 calls: the 70 compiled-out calls go, and so do `sync` and `mknod` (a table in the generator records when each would work). `time` (201) and `rt_sigreturn` (15), handled outside the table, are added.
    - **Wording.** The generated header says the Core "implements" the list rather than "works", since `poll` with a timeout still aborts until M7.
    - **`<sim.h>`.** It gets no `sim_rt_sigreturn`: the call only makes sense as a signal trampoline, and calling it from C corrupts the program. This is the one-to-one rule's single documented exception, decided for M2.
    - **Tests.** `x86Syscalls.test.ts` checks the list against the configuration; it skips the checkout checks when the submodule's `config.h` is absent (CI), while its synthetic cases always run.
- **s68k text tasks (M6 part 1, 2026-10-05).**
    - **New modules.** `src/charset.rs` (Windows-1252 per the WHATWG table) and `src/c_runtime.rs` (EASy68K's `itoa`, uppercase `ultoa`, `"%*d"`, `atoi`).
    - **Display tasks** hand the host finished text: number tasks become `(String)`, and task 17 sends one text. **Read tasks** take what was typed: a raw line for 2, 4 and 18, one key for 5.
    - **Unassigned bytes.** The five Windows-1252 bytes with no character (`$81 $8D $8F $90 $9D`) decode to the same-numbered control characters, as `TextDecoder` does, so every byte round-trips. Other C1 characters are an assembly error.
    - **Diagnostics.** The diagnostic code `character_above_latin1` keeps its name and now means "no Windows-1252 byte". Curly quotes and dashes outside a string raise `unexpected_character` with the old hint.
    - **`atoi` overflow** wraps modulo 2^32; leading whitespace is C's `isspace` set.
    - **Task 2** stores at most 79 characters and drops the rest of the line, where EASy68K keeps the next key for the following read: a documented deviation. Task 5 stores `$0D` for `'\n'` and `'\r'`, and `?` for a character Windows-1252 cannot encode.
    - **Answers.** `answer_interrupt` refuses an answer when nothing is pending, or a line or key answer for another task, leaving the interrupt pending; the wasm boundary throws instead of panicking.
    - **Fixes.** Answering `Terminate` now ends the program; it had been overwritten to Running. The CLI reads a non-UTF-8 source as Windows-1252. `ts-lib/tsconfig.json` sets `"types": []` so the editor's `@types/node` stays out of its build.
- **x86 inline assembly (M2 Core, 2026-10-05).**
    - **What the translator accepts.** Lines between `#APP` and `#NO_APP` are read by the existing GCC-output rules (one Intel-syntax statement per line), plus `syscall` with no operands, which stays an error outside a block. GCC's framing inside blocks is read or dropped, and file-scope blocks work.
    - **Errors.** Every error on a block line has code `inline-assembly` and names the line and the reason:
        - AT&T syntax;
        - a memory operand with no size (`lea` excepted, because NASM and GNU as size such operands differently);
        - comments or several statements on one line;
        - numeric labels;
        - system instructions other than `syscall`;
        - untranslatable directives such as `.rept`.
    - **Profile.** It stays `gcc-intel-v1`: every `#APP` block used to be an error, so no existing output changes.
    - **Oracle.** The capture strips GCC's line markers from the GNU reference, and outcomes gain standard output.
    - **For the editor step.**
        - `translationDiagnostic` must show the translator's message, not "Inline assembly cannot be compiled for x86 yet".
        - The `compilerExplorer.test.ts` case that rejects `nop` changes.
        - C under `-std=c17` has only `__asm__`.
- **Line discipline and adapters (M3 part a, 2026-10-05).**
    - **Model.** The Terminal owns a typed-input queue (`insertText`, `paste`, `pressEnter`, `pressBackspace`, `sendEndOfInput`) shaped like the Keyboard's (`TerminalKeyboard`, which gains `peekCharacter`), and one Line discipline reads either. A read echoes each keystroke as it takes it, so type-ahead shows only once a read takes it; Backspace erases a whole code point. `pendingRead` gives the kind, question, `endOfInput`, source (`terminal` or `keyboard`), the Enter code and the line typed so far, which is already in the transcript.
    - **End of input** on a non-empty line does nothing, as the old prompt did (a tty would submit the partial line); every educational read skips it.
    - **Encodings.** `terminalTextConventions(language)` in `peripherals/terminalText.ts`; the UTF-8 decoder holds back an incomplete tail and keeps a BOM. `write(text)` first ends a character a byte write left incomplete, so output keeps its order. GenericEmulator flushes on every termination path and after a Testcase run.
    - **Interim feeder** (`peripherals/interimPromptFeeder.ts`, removed by part b): with no console attached (`attachConsole()`), a read the queue cannot answer opens the modal prompt and types the answer into the queue. A character read echoes only its character, where the old prompt echoed the whole line.
    - **Dialogs.** `Prompt.confirmOrCancel` and `Prompt.alert`; the app's confirms keep Yes and No. A scripted confirm accepts `cancel`; a message dialog in a scripted run still fails. MIPS and RISC-V input dialogs still stop on Cancel until the Cores take null (M5), and the unused `ask*` handlers go through the input dialog.
    - **x86 standard input.** The adapter asks `readStandardInput` for the read's `rdx` (`core.runtime.getInputMaxBytes()`), calls `provideInput('')` and serves the bytes through the Core's `stdin` callback, because `provideInput(string)` re-encodes its argument and drops leftovers. Checked on 4.0.0: no bytes makes `read` return 0, `read(0, buf, 0)` asks nothing, a one-byte read can split a UTF-8 character, Step works. `ensureLineInput` is gone.
    - **Z80.** `readByte` (the line buffer, else a Screen keystroke in graphical use, else a line) and the synchronous `readBufferedByte`; the device keeps one byte for the re-executed `in`, and `provideInput` became `provideNumber`. The key-available port now also sees the rest of a line.
    - **MARS receiver.** It shows `peekKeystroke(keyboard)` and takes the keystroke only when the program reads the data register, so it never takes one from a read syscall waiting on the same queue; `onInputChange` keeps it current. A Testcase answers it with its lines as bytes ending in `\n`; interactively the Screen keyboard comes first, then the Terminal's queue. The "Automated testcases cannot type into the Screen" sentence of the MIPS and RISC-V keyboard Lectures is now out of date.
    - **Scripted character reads** take the first code point, so MIPS and RISC-V read char accepts a longer scripted value instead of failing.
- **MARS and RARS services (M5 part 1, 2026-10-05).**
    - **Handler API.** `printString(text)` is the only output path, for services 1–4, 11 and 34–36.
        - The reads (`readInt`, `readFloat`, `readDouble`, `readString`, `readChar`) return the typed string.
        - `inputDialog` returns `string | null`; `confirm` returns 0, 1 or 2; `outputDialog` is awaited.
        - `writeFile` returns the count or -1. `readFile(fd, length)` and `stdIn(length)` return `[count, bytes]`. Bytes cross as `number[]`.
        - `printInt`/`printFloat`/`printDouble`/`printChar`, the `ask*` handlers, `log` and `logLine` are gone.
        - `DialogType` gains `PLAIN_MESSAGE = -1`.
    - **Formatting.** `JavaNumberText` implements JDK 21's `Float`/`Double.toString` without `long`, so TeaVM stays fast (about 5 µs a double). It also implements Java's parse grammar, correctly rounded, floats directly. `parseInt` takes Java 21's Unicode digits from its own table, since TeaVM's `Character.digit` also accepts numerals such as `²`.
    - **Golden vectors.** They are generated by `GoldenVectors.java` on JDK 21 and committed under `ts/test/fixtures/java-numbers/`: 4,316 floats, 5,996 doubles and about 5,000 parse lines, all matching. Uncommitted checks also matched every non-negative float bit pattern, plus millions of random cases.
    - **Read char.** It takes the first character, as MARS 4.5 and RARS 1.6 do (`"\n"` is 10). An empty answer stops the run with "invalid char input (syscall 12)", as both references do. Input dialog 51 does not trim, as the reference does not.
    - **Failures.** A failed `readFile` (-1) reaches the program as -1, where the Java side used to turn it into end of file. A handler breaking its contract (a non-string answer, `undefined` from `inputDialog`, a malformed tuple) fails the run. A `writeFile` count above the request is clamped.
    - **Assembler literals.** The assemblers' `.float`/`.double` literals still parse with TeaVM's parser: 54 of 803 golden strings assemble to different bits (`.double 4.9e-324` becomes 0). They move to `JavaNumberText` in part 2.
- **s68k errors, files and settings (M6 part 2, 2026-10-06).**
    - **Answers.** Each interrupt is answered only by the answer of the same name, or by `Terminate`.
    - **Files.** 50 `CloseAllFiles` → bool; 51 `OpenFile(path)` → `{handle, read_only} | null`; 52 `NewFile(path)` → `handle | null`; 53 `ReadFile {handle, count}` → `Uint8Array | null`; 54 `WriteFile {handle, bytes}` → bool; 55 `PositionFile {handle, offset}` → bool; 56 `CloseFile` → bool; 57 `DeleteFile(path)` → bool; 58 `FileDialog {mode, title, filter, path}` → `string | null`; 59 `FileExists(path)` → `"Writable" | "ReadOnly" | "Missing"`.
    - **Results.** The Core writes EASy68K's D0.W code, the file number to D1.L (-1 when nothing opened) and the read count to D2.L. Paths are at most 255 characters, decoded from Windows-1252, with `\` sent as `/`. The host owns file numbers (lowest free, at most 8); the Core keeps no handle table (s68k ADR 0005).
    - **Plan correction.** The plan was wrong about read-only files; `SIMOPS2.CPP` settles it: task 51 reports 3 when it opens a read-only file, and a later write fails with 2.
    - **Deviations, documented.**
        - A zero-byte read reports 2.
        - A count wrapping past 4 GB reports 2.
        - Task 16 with D1.B ≥ 4, and task 58 with a mode other than 0 or 1, end the program, where EASy68K does nothing.
    - **Sound and settings.** Sound 70–77 are interrupts with decoded arguments, answered bool. Tasks 12 and 16 raise no interrupt: they set Core state read through `getInputSettings()` → `{echo, prompt, line_feed}`, on by default per run and journaled as `SetInputSettings`. Bytes cross as `Uint8Array` (an in-crate serde-bytes type).
    - **Errors.**
        - New error types: `UnsupportedTrapTask {task}`, `InvalidTrapArgument {task, reason}`, `NoPendingInterrupt`, `InvalidAnswer {interrupt, reason}`, `InvalidArgument`.
        - Every runtime error now ends the program, division by zero and address errors included. `getTermination()` returns `TerminateTask | EndOfProgram | TerminatedByHost | Exception(error)` and is undone by Undo.
        - Undo of a trap with a pending interrupt clears it.
        - The wasm boundary throws typed objects and no longer panics.
    - **CLI.** It runs files on disk relative to the entry file, asks for 58's path on the terminal and prints why the program ended. The README has a 3.0.0 migration table.
- **`<sim.h>` for MIPS and RISC-V (M1, 2026-10-06).**
    - **Generator.** `scripts/sim-header/simHeader.mjs` builds the text and has no imports; `generate.mjs` (`--check` for drift) resolves the editor's `$lib/` and extensionless imports, so plain Node reads `mipsSyscalls.ts`, `riscvSyscalls.ts`, `MarsDevices.ts` and `marsDisplay.ts`. The device registers come from `MarsDevices.ts`, which the Screen chapter (`documentation/mars/screen.ts`) reads too. The three headers are about 20 KB each.
    - **Function shape.** One register variable per register. An argument and a result in the same register and of the same type share one `+r` operand; otherwise the result gets a variable of its own, `result`, in that register. Statuses are stored through their pointer after the call.
    - **Doc comments.** Title and service number, then the Documentation's argument and result descriptions in full. The first-sentence summary would cut the random services at "i.d.".
    - **Static-data cap, measured.** On all three Cores it is 196,608 bytes, from `0x10010000` to the heap at `0x10040000`, RISC-V and RISC-V-64 included: "below 524,288 on RISC-V" does not hold for GNU-profile Builds. `SIM_SCREEN` also asserts MARS's display sizes and units, which the directive would otherwise snap.
    - **Source map and Workbench.**
        - Only `<sim.h>` maps; the Runtime library's headers still map to no line.
        - On Step, Run and Undo, the mapped pair's source pane follows the current instruction to the File it came from: into `@runtime/include/sim.h` and back, and into a Project header's inlined function too.
        - The header takes Breakpoints, during a Debug session as well.
    - **Output filter.** It also drops a code line's trailing `# @screen` comment. Clang's source annotations write `.type screen,@object  # @screen`, which a Build read as a second directive, or as the only one for a global named `screen`.
    - **Diagnostics.** GCC's "In file included from" lines no longer become an empty error on the source File.
    - **Fixtures.** `scripts/sim-header/capture-fixtures.mjs` captures 32 compiles into `src/lib/sourceRuntime/fixtures/sim/`, keeping only the lines the editor reads. The program calling every service skips RISC-V 53, and prints only floats that Java and JavaScript format alike, until M5.
- **Shared MARS/RARS handlers (M4, 2026-10-06).** `src/lib/languages/mars/marsHandlers.ts` holds what the MIPS and RISC-V adapters duplicated: the handlers, questions and errors, the per-instruction FileSystem frame, `handlerBytes`, `normalizeUndoSize` and `toHaltLimit`.
    - **Structure.** `MarsHandlers` owns the execution generation the handlers read, and the adapters call `beginExecution()` where they captured it. Each adapter supplies the peripherals (read at use, since a Testcase swaps the clock), the execution controller, `setInterrupt`, the FileSystem session (read lazily) and its `programCounter`.
    - **Types.** `MarsHandlerMap` is declared in the module, and each adapter's `registerHandlers` checks it against its own Core's types, so the M5 shape change fails to compile where it no longer matches.
    - **What stays per Core.** Step and run results (boolean against `StopReason`) and the `ended` flag stay in the adapters until the M5 adoption. Behaviour is unchanged.
- **`<sim.h>` for x86 (M2 editor, 2026-10-06).**
    - **Bindings.** `src/lib/documentation/x86/syscallBinding.ts` turns each row of `x86Syscalls.ts` into its C function, and both the Documentation's _From C_ field and `generate.mjs` read it; `simHeader.mjs` writes the bodies into `x86_64.h` (110 functions, about 42 KB).
    - **Types.** A label that points at memory is `const void *` when the kernel only reads it and `void *` when it writes there; every other label is `long`.
        - Pointers: buffers, paths, strings, iovec arrays, mmap's address, clock_gettime's `timespec` and strace's `i_`/`o_`/`io_` structures.
        - Two labels are read-only despite their wording: iovec arrays (the kernel reads the array either way) and utimensat's `o_time2`.
        - strace's bare `value` stays `long` even where the kernel reads a pointer, in 28 calls such as `uname`, `gettimeofday`, `poll` and `ioctl`, so C passes `(long)&x` there. Retyping them once M7's list names their types breaks sources that cast, since GCC 14 makes int-to-pointer conversion an error.
    - **Names.** Parameters take Linux's names where they are clear (`fd`, `buffer`, `count`, `statbuf`, `request`/`remaining`, `tp`, `clockid`), and a name that repeats is numbered (`path1`, `path2`). An unknown label stops the generator; strace's prefixes and the Documentation's `arg1` fall back. M7's in-flight configuration (131 calls) uses no label the table lacks; after regenerating `x86Syscalls.ts`, run `generate.mjs`, or the drift test fails.
    - **Shape.** Each function returns `long`; `exit` and `exit_group` are `void` and `noreturn`. Each doc comment is "name, syscall N." followed by the Documentation's description, where the call has one.
    - **rt_sigreturn.** It has no function: the header's preamble says why, and its _From C_ field says "None in `<sim.h>`".
    - **Documentation.** _From C_ is each entry's last field, and it stays out of the search text, as it does on MIPS and RISC-V.
    - **Compile.** `X86_HEADER_NAMES` includes `sim.h`, and the missing-header Hint names it.
        - An `inline-assembly` Diagnostic shows the translator's own message. On 4.0.0 that message is the old rejection, located in the header.
        - The Hint (a `.asm` File) stays, since it holds for both translators.
        - `scripts/runtime/capture-compile-fixtures.mjs` uploads `<sim.h>` for x86 too.
    - **Tests.**
        - `fixtures/sim/x86/` holds six captures: a program calling `sim_read`, `sim_write`, `sim_getpid`, `sim_clock_gettime` and `sim_exit_group`, in C and C++ at `-O0` and `-O2`, and a `sim_fork` compile error, in C and C++.
        - The runs through the Start unit apply when the translator accepts a `syscall` block, a capability probe; on 4.0.0 the test checks the old rejection instead.
        - A host GCC compiles every function in C17 and C++17 under `-Wall -Wextra -Werror`.
- **Correction to the x86 bindings (decided 2026-10-06).** The calls whose generated labels are only `value` but whose kernel argument is a pointer (`uname`, `gettimeofday`, `poll`, `ioctl`'s argument and the rest of the 28) get their real pointer types through an override table in `src/lib/documentation/x86/syscallBinding.ts`, before any release, rather than `long` with a cast. Retyping them later would break programs, since GCC 14 rejects an integer passed as a pointer. This is done in the editor sync after Blink's build configuration changes, which also regenerates `x86Syscalls.ts` and `<sim.h>`, since that configuration now compiles 131 calls.
- **The console (M3 part b, 2026-10-06).** `src/components/shared/terminal/TerminalConsole.svelte` replaces `Console.svelte` in `TerminalView` and `StdOutRenderer`; the interim feeder, `Prompt.askLine` and the modal's End of input are gone, so every read waits for the console.
    - **Input.** A visually hidden textarea at the caret takes the keys (16px, so a phone does not zoom; `autocapitalize` off, since the field is always empty).
