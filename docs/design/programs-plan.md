## Decisions taken while planning

Taken by default, for the owner to overturn:

1. **Compile accepts a source without `main`.** `compilerExplorer.ts` stops throwing `mainRequired` and reports `definesMain` on its result: `.globl`/`.global main` with a `main:` label on MIPS and RISC-V, a `global`-bound `main` in `symbols.defined` on x86. Decision 9 needs the companion `add.c` to compile. So that a forgotten `main` still says something, a Compile that makes no Program because there is none logs a note: "sort.c defines no main, so no program was made for it."
2. **A Program whose Entry is C or C++ source moves on Compile.** Earlier data (a "Set as entry file" on `main.c`), a Playground's authored C entry and test fixtures can have one. Compiling that source moves the Program, its Settings and Testcases, to the Generated assembly, `main` or not; until then a Build of it says to Compile first, as today. Normalization keeps such an Entry as it is.
3. **No Program, new shape everywhere.** The earlier shape cannot say "no Program" (its reader invents `main.<ext>`), so a Project with none is written in the new shape: archive version 3, share link and IndexedDB alike; it has no single-file export.
4. **Share links follow the archive rule.** One Program writes the earlier shape, so a cached older app (the service worker) still opens it; several or none write the new one. One helper, `legacyProjectShape`, serves archives, the exported file and share links.
5. **Precedence.** Input with `programs` uses it and ignores the old fields; input without it builds one Program from them. `Project.set` drops its own `programs` and `selectedProgram` when the merged data brings old fields and no `programs`, as it already drops `files` for legacy `code`.
6. **A move that replaces an Entry** is a host delete of the replaced File's Program (with decision 7's prompt) followed by a host rename of the moved one.
7. **The old Project accessors go.** `entry`, `settings`, `testcases` and `display` getters and setters stay through M1 as deprecated accessors of the Selected program, so the app keeps working between milestones, and are removed in M5, letting the type checker find any consumer left. `code` stays and means the Selected program's Entry text (`''` with no Program).
8. **Docks per Entry pane.** Outside a Debug session every pane showing an Entry has the dock with Build and Test; during a session only `controlsGroup` carries the session controls, as today. `controlsGroup` is the session's pane during a session, else the pane showing the Selected program's Entry, else the last pane showing any Entry. The tablet's one bar builds `controlsGroup`'s Program.
9. **Only the Selected program's live errors disable Build.** Live analysis follows `sourceInput`; analysing every Program would multiply the worker's work. A pane's Build of another Program is enabled and the Build reports its errors.
10. **One effect applies a selection.** The session pushes the Selected program's undo budgets, Arguments and Display to the Emulator whenever `project.selectedProgram` changes, and clears `testcasesResult` and `failedBuild`, so the picker, Build, Test, Compile, delete and rule 8 all stay correct without each doing it.
11. **Tabs mirror the Explorer.** `FileTabs` marks every Entry, the Selected program's in the accent colour; the mark keeps its `ENTRY` text.
12. **The x86 upload question** is asked only when the Project already has a Program and the Executable is not an Entry: "Create a program for chall?". With none, rule 8 makes it without asking.
13. **The Coding agent's writes are host actions.** Its `setFile` and `deleteFile` go through the session's hooks, and `delete_file` no longer refuses the sole Entry: deleting it deletes the Program, which its result says. It asks nothing, as it asks nothing today.
14. **Settings panel.** The Instruction set stays under Project; a Program section holds the Settings and Display, titled with the label when there are two Programs or more, and says how to make a Program when there is none.

## Milestones

M1 first. M2 and M3 run in parallel on disjoint files once M1's API exists; M4a and M4b in parallel after M3; M5 last.

### M1: The Project record

- `lib/Project.svelte.ts`: `type Program = { settings: ProjectSettingsDecisions; testcases: Testcase[]; display?: ProjectDisplay }`; `ProjectData.programs: Record<string, Program>` (built with `Object.fromEntries`, a plain prototype, so Svelte proxies it and Testcases edited in place stay reactive) and `selectedProgram?: string`; `StoredProject` gains both as `unknown` and keeps the old fields as legacy input.
- `cleanPrograms` beside `cleanEditorTabs`: keys pass `isValidFilePath` and may name missing Files; values through `cleanProjectSettings`, `cleanTestcases`, `cleanDisplay`. `selectedProgram` is kept when it is a key, else the first Program by label, else absent.
- `normalizeProjectData`: new shape through `cleanPrograms`; old shape (and v1 `code`) through `pickEntry` into one selected Program (decision 5). `programs: {}` stays empty.
- `makeProject`: getters `programs`, `selectedProgram`, `selected` (the Selected program or undefined) and `program(entry)`; methods `createProgram(entry)` (selects it), `selectProgram(entry)`, `removeProgram(entry)` (selects the first left by label), `renameProgram(from, to)` beside `renameCompilationFile`, `setProgramSettings(entry, v)`, `setProgramTestcases(entry, v)`, `setProgramDisplay(entry, v)`; Program mutations assert the FileSystem is editable, like the `entry` setter. Programs are replaced immutably, never `state.programs[path] = …`. `toObject`, `contentKey`, `set()` (lock check, legacy reset, decision 5, copy `selectedProgram`), `getCode`/`setCode` (Selected program; refuse to write with none). Deprecated accessors per decision 7.
- `lib/commandLine.ts`: `programLabel(entry, compilations, files)`, the source while its record names an existing File, else the Entry path; `programsByLabel(project)` for the picker order and "first left".
- `lib/projectSettings.ts`: `hasDecidedSettings(decisions)` for decision 7's prompt; doc comments say Program.
- `lib/buildSources.ts`: `programBuildSources(project, entry = project.selectedProgram)` taking that Program's Settings; `projectBuildSources` stays structural.
- `legacyProjectShape(snapshot)` (one Program → `entry`, `settings`, `testcases`, `display?`; else undefined), used by `projectArchive.ts` (version rule `programs !== 1 ? 3 : edited ? 2 : 1`, `parseManifest` accepting 3, `validateProjectMetadata` branching by version, `isSingleSourceProject`/`isLegacyLinkedFileCompatible` requiring exactly one Program whose Entry is the only plain File), by `toExternal` (throws unless one Program), and by `createSharePayload` (decisions 3, 4).
- `lib/storage/db.ts`: the v1→v2 upgrade deletes the old fields after assigning the normalized row. No new Dexie version.
- `lib/executableImport.ts` writes `programs`; `lib/exam.ts` reads the one Program's Entry text and Testcases.
- Tests: `Project.test.ts`, `projectArchive.test.ts` (versions 1-3 round trips, one/several/no Program, precedence), `db.test.ts`, `buildSources.test.ts`, `projectSettings.test.ts`, `executables.test.ts`, a share-link round trip.

### M2: Compile and Playgrounds

- `compilerExplorer.ts`: `definesMain` instead of `mainRequired` (decision 1); update `compilerExplorer.test.ts`.
- `compileProjectSource.ts`: snapshot without `project.entry`; after writing the output, the Programs change in this order. Order: an existing Program at the output is selected; else a Program whose Entry is the source moves to the output (decision 2); else `definesMain` creates and selects one, unless the caller passes `makePrograms: false`; else nothing. The result gains `program: 'selected' | 'moved' | 'created' | 'none'` and `definesMain`.
- `PlaygroundSession.svelte.ts`: start from the one Program's Entry, drop the keep-the-authored-entry rule (:95-111) and compile with `makePrograms: false`, since a Playground has exactly one Program (design decision 12); `playgroundProgram.ts` reads the one Program; `PlaygroundSession.dom.test.ts:109` encodes `{ files, entry: selectedProgram, compilations }`.

## Implementation notes (2026-10-21)

Where the milestones departed from the plan above:

- **M1.** The per-Program setters take no FileSystem lock, since `syncDisplay` writes the Display during a Debug session. `set()` given old fields and no `programs` rebuilds one Program. Archive version 3 is written for zero Programs as well as several. Share links use the earlier shape for one Program.
- **M2.** `definesMain` accepts Clang's trailing comments. The x86 companion test uses `sum.c`, because the translator renames `add`.
- **M3.** `build(entry)` and `test(entry)` push the new Program's Settings synchronously, as the selection effect would run after Compile read them. C and C++ panes never show Build or Test, even when a C File is an Entry from earlier data. Programs are also locked during a Debug session. With no Program the sources use `main.<ext>` with `NO_PROGRAM_MESSAGE`, which the M68K and Z80 checkers ignore. Two qualifying `main.*` Files make no Program, and an assembly-named File stored as bytes does not qualify. Compile logs the no-`main` note.
- **M4a.** The picker is a component of its own, `ProgramPicker.svelte`. `SidePanel` computes the header suffix. The Display is a part of the Program section. Remove program asks "Remove the program of main.s? This deletes its Settings and 3 Testcases; the File stays." Keep as File does not ask the x86 question.
- **M4b.** The host passes the agent's no-program message, because importing the session would pull its module graph into the chat, exam and lecture bundles. When the agent is hosted in the Workbench, its writes and deletes go through the session's hooks; otherwise they go through the Project API.
- **M5.** The deprecated accessors are gone, and the tests use `selected`, `program(entry)` and `programBuildSources`. `compileProjectSource`'s `makePrograms` became `newProgram: 'create' | 'move' | 'none'`. Playgrounds pass `none`. The chat page's agent passes `move` (the `newProgram` prop of `DefaultCodingAgent`, through the tool context), which moves the Selected program to a Generated assembly that defines `main`, as the one Entry moved, and makes one only when there is none. A Playground with no Program gives `main.<ext>` and `PLAYGROUND_NO_PROGRAM_MESSAGE` as its sources, so the Interactive editor's live check runs and says why nothing builds. The Testcases list is keyed by the Selected program. `SettingsSectionId` lists the panel's sections (`program` in place of `display`), and `SettingsTarget` adds `display` for `openSettings('display')`.
- **Review fixes** (2026-10-21, after a review of the uncommitted work):
    - The session's `testing` is `$state`, so the picker and `languageEditable` unlock when a test run ends; the effects that only ask about it read it untracked.
    - The Explorer has no long press of its own, and iOS Safari fires no `contextmenu` on one, so a touch screen could not reach the Program items. Its touch-only row buttons now carry "New program from this file" (`FaFlag`) on the rows whose menu offers it and "Remove program" (`FaRegFlag`) on Entry rows; pointer screens still have no row button. Taken by default, for the owner to overturn.
    - On a touch screen the shown row's buttons are laid out beside its marks rather than over them, so the Entry mark and the counts stay visible, and a hidden row's buttons no longer take taps. Desktop rows have no buttons and were not affected.
    - A rename or move of an Entry onto the missing Entry of a Program with Settings decided or Testcases asks first ("Replace the program of b.s? This deletes its Settings and 2 Testcases."), and No keeps the File where it was.
    - A rename makes the first Program only when the File did not qualify under its old name, so renaming a `main.s` whose Program was removed makes none.
    - `toObject` rebuilds `programs` and `fileViews` from their own entries, so an Entry or a File named `__proto__` survives a save. No other writer snapshots the maps. Its snapshots stay inside the returned object, because Svelte's server build drops a `$state.snapshot` that is a declaration's whole value, which the node tests run.
    - A pane's Build and Test make that pane the execution pane (`build(entry, group)`, `test(entry, group)`), so the session's controls and first stop open there.
    - `controlsGroup` skips C and C++ panes when it picks a pane by Program, so the tablet bar lands on a pane with Build.
    - The Explorer is locked during a test run too (`session.filesLocked`), and its delete, move and rename re-check the lock after their question. The Coding agent's writes are not locked by a test run.
    - The MIPS/RISC-V, M68K and Z80 analysis adapters, like x86's, report `assemblyError` or a missing Entry ("Entry file not found: gone.s") as the one Diagnostic through a shared `unresolvedSnapshot`, so nothing logs "analysis failed".
    - `getM68kErrorMessage` no longer starts a message without a line with a space, so the Build toast reads "Error compiling code. Entry file not found: gone.s". The agent prompt says compile_source makes the generated assembly "the selected program's Entry file", which holds in `create` and in `move` mode.
    - On a phone the bottom strip's tabs become icons, named in their tooltip and `aria-label`, while the picker shows. The picker's trigger shrinks with an ellipsized label, so the panel does not overflow at 390 px.
    - Owner's follow-up (2026-10-21): the picker's arrow is a chevron icon that turns over while the list is open, the list always opens above the strip and has a border (opt-in `openAbove`, `chevron` and `listStyle` props of `Select.svelte`, so the app's other selects are unchanged), and the compact layout's Fold button is gone with the folded state it kept (`BottomPanel` lost its `open` and `actions` props).
