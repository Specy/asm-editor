Other findings need a more focused follow-up:

- **U07–U08:** current Svelte/TypeScript probes support removing the input type-setting action, unused legacy event bubbling, and Monaco worker-assignment suppression. Exercise actual text/password/numeric inputs and run the full project check before accepting those changes.
- **S07:** the five instruction pages' `__tla` promise shim appears obsolete. Keep their client-only dynamic imports; verify a fresh prerender build and embedded-editor loading before removing the shim.
- **S08:** course client loaders merely return sibling server-loader data. Confirm generated types and both direct and client navigation before deleting them.
- **E07–E08:** resolve the test-only conversion helpers and disconnected Z80 color metadata. Prefer removal of unused helpers over changing working behavior just to create a caller.
- **E04:** native x86 analysis computes expanded assembly and line maps just to obtain include reachability. A dedicated shared walker could avoid that work, but reachability itself remains necessary.
- **E10:** the x86 instruction-per-millisecond estimate predates major Core execution changes. Remeasure throughput and Stop responsiveness before adjusting this issue-specific calibration; no new performance measurement was made here.

The larger x86 cleanup needs precise API boundaries. Project compile/check and compiled-instruction APIs already existed in 3.0.0, which was independently checked against the [published 3.0.0 tarball](https://registry.npmjs.org/@specy/x86/-/x86-3.0.0.tgz). Archive linking and Undo recording/count APIs arrived later. The new 4.0.0 pin makes those later capabilities available too; the emulator report separates their obsolete guards from source mapping, include reachability, and history behavior that still serve the product.

Several apparent hacks should remain: persisted-data migrations, old project/exam links, legacy linked-source write-back, the Monaco overflow-hover workaround, the icon-sizing contract, test-start repaint yields, and editor/connector layout scheduling. Their current consumers or failure modes remain present. “Legacy” parity comments also describe accepted behavior rather than dead implementations.

The audit recommended separating deletion-only changes from API, input, and lazy-loading changes. The former need reference checks and normal project validation; the latter also need the focused behavior checks listed in their reports. Avoid mixing a Core upgrade or typography changes into the first deletion batch.
