# x86 links the Entry's unit and takes the other Files as needed

Amended in part by [ADR 0039](./0039-x86-links-start-objects-before-user-and-support-archives.md).

Update 2026-11-03: MIPS and RISC-V adopt the same rule for their GNU-profile units, compiled C and C++ ([asmOS portability](../design/asmos-portability.md), decision 11). The Entry's unit, with what it includes, is always linked. The Project's other GNU-profile units are linked only when they define a symbol the program still needs. Each unit keeps its own local labels and file-scope names, through the per-unit link the MARS and RARS Cores already use for Runtime library members. As implemented the same day: units link only for GNU-profile Builds, so a Build in the MARS or RARS dialect links its includes alone. The Cores cache only each unit's parse and its statements' encodings, by their exact text, not the layout or emission. A duplicate strong global is an error only among the units the link takes, as `ld` reports it. The owner decided the same day that x86 follows the same rule, where it had rejected one across every user unit ([ADR 0039](./0039-x86-links-start-objects-before-user-and-support-archives.md), amended 2026-11-03).

Update 2026-11-04: a hand-written assembly File joins a Build only when the program needs a symbol it defines, found by a quick scan of its global declarations before anything is assembled. A File the program does not need is never assembled, so an unrelated File cannot break a Build. This holds on every Target, x86 included, where every File used to be assembled and any error failed the Build. On MIPS and RISC-V a needed hand-written File is assembled under the Build's GNU profile, and one written in MARS's or RARS's dialect fails with an error saying it must be GNU syntax ([asmos-stage2.md](../design/asmos-stage2.md), decision 10). A File holding `.ktext` gets no special treatment: the processor enters an exception handler by its address, which no program names, so a C program asks for the handler's File with `<sim.h>`'s `SIM_LINK(name)`, a file-scope `.globl` of a name the unit does not define, which the link counts as a need as `ld` counts an undefined global, the way `ld -u` asks for a member. Two linked Files that both hold `.ktext` are an error; Files the link does not take are never compared. (Revised at review the same day: as first implemented, every File holding `.ktext` was linked, and an unrelated MARS interrupt lab then took over a C program's faults.) On x86, where NASM keeps no symbol for an `extern` nothing uses, NASM's `required` does what `.globl` does, and the translator of compiled C writes it for such a `.globl`.

An x86 Build links the way a C toolchain links objects and a static library: the Entry file's unit is always linked, and every other source File becomes a member of an archive that `ld` takes only to resolve a symbol the program still needs, including `_start`. Library units supplied beside the Project, such as the editor's start code for compiled C and C++, come first in that archive, so they win over a Project File for the same symbol. A default Project's `main.asm`, which defines `_start`, therefore stays out of a Build whose Entry is Generated assembly, two programs can share a Project with the Entry choosing which runs, and C and NASM still call each other because a File comes in with the symbols it defines. Every File is still assembled and checked; a File nothing refers to is just not linked. This replaces the rule, kept on 2026-10-05 as gate 9 of the [translation plan](../design/x86-compiler-assembly-translation-plan.md), that every x86 source File links, and it changes `@specy/x86` incompatibly from 3.x, which linked every unit of a Project.

## Considered options

Keeping every File linked made the start code's `_start` clash with a default `main.asm` on a new Project's first compiled Build, and a live warning only explained it. Linking the Entry's include unit alone, as MARS and RARS do, would stop NASM and compiled C from calling each other across Files. A weak `_start` in the start code would let a hand-written one win silently, so a program would start in assembly while its compiled `main` never ran.
